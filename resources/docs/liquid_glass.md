# Liquid Glass rendering

`LiquidGlassSurface` is a decorative child of a positioned, isolated surface. It does not wrap controls or change their layout. Chromium supplies the live backdrop to an SVG filter through `backdrop-filter: url(...)`. `SourceGraphic` is the real painted content behind the plate; scrolling, text updates, images and transforms are handled by the compositor. There is no application screenshot capture, DOM clone or WebGL context.

`liquidGlassGeometry.ts` generates a vector normal field from the plate dimensions and four corner radii. The field describes the optical geometry, not background content. The displacement profile v2 is non-monotonic ("folded lens"): three smoothstep lobes over the normalized edge distance produce rim compression (peak near 40% of the band), a fold that pulls inner rings back over content already sampled near the rim — the perceived edge inversion of real convex glass — and a slight magnification dip (−0.16) before settling to exactly zero at both the rim and the inner band edge. A sharp, unmoved rim line and a seamless join to the flat center are preserved. Rays are traced inward; the host clamps the displacement scale to 0.9 × band so the peak sample offset never leaves the plate. Three nearby displacement scales split the RGB channels subtly, only where normals displace content, and the chain ends with a saturation lift (default 1.35) plus a 4% brightness transfer that restores the vividness the tint veil damps. ResizeObserver rebuilds geometry only when dimensions change. Transforms move the plate and its optical coordinates together.

Blur is two-stage: the SVG filter applies a light (2px) band blur so refraction stays recognizable, and an optional `centerBlur` adds a real central blur through the masked `.liquid-glass-readability` layer. Current hosts keep `centerBlur` at zero so the center matches the band exactly; the readability veil alone (0.18 tint on InputBar/QuickLauncher) separates input text from background content.

Hosts: InputBar and QuickLauncher use refraction 30, 28px band, tint 0.18; dropdown menus (model selector, reasoning, attach, skills, slash, session mode, permission profile, TabBar menus, harness explorer, harness project menu) use refraction 12, 14px band, tint 0.66; docked panels (TodoPanel, Questionnaire) use refraction 14, 16px band, tint 0.4; small pills (scroll-to-bottom, citation pill) use refraction 10, 10px band, tint 0.3 and specular 0.12.

Parameters are `refraction` (SVG displacement scale in CSS pixels), `blur` (standard deviation in CSS pixels), `chromaticAberration` (channel scale separation), `specular` (0–0.3), `opacity` (tint opacity, 0–1), and `distortionRadius` (edge band in CSS pixels). Current hosts use circular CSS corner radii; elliptical animated radii are not an established contract. InputBar uses restrained transparent defaults; menus use a denser tint for readability.

InputBar and QuickLauncher use `blur={2}` across the entire optical surface with `centerBlur={0}` (center blur matches the band by design) and `centerAttenuation={0.18}`: a theme-tinted central veil below the text area, fading to zero across the optical edge band. This separates typed text from background content while retaining the displacement at the edges. The veil is mounted only with the Maximum material and removed on the same lifecycle. Both central controls default to zero on other surfaces.

While optics are mounted, the host's own frost must be neutral: `.perf-max [data-liquid-glass='active']` rules strip `true-glass` (including non-menu-host variants such as the scroll pill and citation pill) and `liquid-glass-docked` backgrounds and backdrop filters, and carry a hover restoration for small pills. Without this, host frost and SVG blur would stack.

The shared performance subscription keeps App, Settings and surfaces synchronized using the existing `prism-performance-mode` storage key. Only visible Maximum surfaces mount filter definitions. Medium, Performance, document hiding, reduced motion and reduced transparency remove the optical children. Observers disconnect on teardown. There is no JavaScript frame loop. Chromium owns internal filter allocations and device scale; application code cannot explicitly dispose compositor textures. No GPU memory leak claim follows from merely counting DOM nodes.

Keep filters on the decorative layer, never on a menu-host ancestor. Opacity/filter/mask ancestors establish backdrop boundaries in Chromium: during ancestor opacity transitions, sampling can be restricted until opacity returns to one. Do not add new translucent ancestors around this material. The standard appearance is retained when refraction is disabled.

Run `npm run typecheck` and `node --experimental-strip-types scripts/liquid-glass-validation.mts`. The latter launches an isolated Electron window with controlled background content and real InputBar/selectors. It compares decoded edge pixels with displacement enabled/disabled, checks mode teardown, resize, scroll and accessibility fallbacks. PNGs are written to the OS temporary directory; no user chats or account data are used. Fixtures are development-only and are not referenced by the application entrypoint.

Manual acceptance in the full application remains necessary: check streaming text, photos, colored content, focus, menu overlap, zoom/DPR, split panes, and rapid mode changes. Inspect compositor cost and GPU memory over extended use on the target hardware. Synthetic fixture results do not establish a universal frame-rate or GPU-memory guarantee.
